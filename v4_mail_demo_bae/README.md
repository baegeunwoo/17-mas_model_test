# PNT 회의록 서비스 · v4

2026-11-13 최신 B2 작업본을 팀원 PC에서 실행할 수 있도록 정리한 Git 소스 패키지입니다.
현재 사용 중인 `V3_시연용`의 화면과 기능을 포함합니다. `v4`는 전달 폴더명이며 최신 화면의 소스 경로는 `work/v3/`입니다.

## 실행 순서 · Windows

1. Git에서 내려받은 `2주차/v4` 폴더를 통째로 사용합니다. ZIP이면 먼저 압축을 풉니다.
2. **Python 3.12 64비트**를 설치합니다. Python Launcher 또는 PATH 등록을 선택합니다.
3. `01_처음한번_설치.cmd` 실행 — 최초 한 번, 인터넷 필요.
4. `02_서비스실행.cmd` 실행 — 실행 창을 열어 둡니다.
5. 브라우저에서 **http://127.0.0.1:8773/** 접속.

화면 빌드 결과를 포함했으므로 기본 실행에 Node.js는 필요하지 않습니다.
종료는 실행 창에서 `Ctrl+C`입니다. 같은 포트가 사용 중이면 해당 실행 창에서 기존 v4를 종료한 후 다시 실행합니다.
이전 V3(8771)·시연 작업본(8772)과 포트·로그인 쿠키·데이터 경로를 분리했습니다.

## 포함 기능

- 프로젝트별 홈, 캘린더·메모, 프로젝트 생성·휴지통.
- 여러 회의록 동시 등록, 프로젝트 연결 제안, 분석 대기·진행 상태 및 조건부 예상 시간 표시.
- 회의록 원본, AI 정리, 근거 대조, 본문 수정·재분석.
- 항목별 요구·변경 이력, 합의·요청·보류·철회 구분, 기록 수정.
- 검색·근거 기반 AI 질문, 통합 휴지통·복원·삭제, 화면 테마·글자 크기 설정.
- 회의록 고객 승인 메일: PM이 보낸 링크에서 고객이 본문을 확인하고 승인·반려.
- 안건 번호가 없는 회의록도 주제별로 묶고 이전 회의의 같은 주제와 연결(회의록 상세의 **주제별 안건** 탭).
- 상단 **주제 흐름** 메뉴: 프로젝트별로 주제마다 처음 나온 회의·최근 회의·현재 값·미결 사항을 표로 보고, 펼치면 회의별 원문 문장과 변경 기록을 날짜순으로 봅니다(`GET /api/v3/projects/{프로젝트ID}/topics`, 승인 정보는 표시하지 않음).
  제목에 프로젝트 이름·코드·PM·회의 기간을 표시하고, 회의록 제목에 공통으로 나온 설비명(예: 제박기 3호기)을 함께 보여 줍니다. PM은 이 화면에서 프로젝트 이름을 바꿀 수 있습니다(`PATCH /api/v3/projects/{프로젝트ID}`).
- 회의록 상세의 **원본** 탭: 업로드한 원본이 PDF·Word면 페이지 이미지를, 텍스트 회의록이면 회의록 양식(제목 바, 회의명·프로젝트명·일시·장소·참석자·작성자 표, 회의 안건·논의 내용·결정 사항·추가 확인 사항·후속 조치)의 A4 문서로 보여 줍니다. 논의 내용은 원문 그대로이고, 3~5번은 AI 정리·변경 기록에서 가져온다고 표시합니다. `PDF로 저장·인쇄`로 브라우저에서 PDF로 저장할 수 있습니다.

현재 화면은 B2 중심입니다. 업무 배정·완료 검토와 D3 보고서 작성 화면은 포함하지 않습니다.
`work/v17/`은 최신 서비스가 함께 사용하는 저장소·문서·권한 등의 공통 코드이므로 삭제하면 안 됩니다.
AI 결과는 원문과 대조하고 수정할 수 있습니다. 예상 시간은 유사한 실제 처리 이력이 충분할 때만 표시됩니다.

## 고객 승인 메일

회의록 상세 화면에서 프로젝트 PM이 **고객 승인 메일 보내기**를 누르면 고객에게 승인 요청 메일을 보냅니다.

1. 받는 사람 이메일(필수), 이름, 전달 메시지를 입력해 보냅니다.
2. 고객은 메일의 링크(`/#/approval/토큰`)에서 로그인 없이 회의록 본문을 확인하고 **승인** 또는 **반려**를 누릅니다. 링크를 여는 것만으로는 처리되지 않습니다.
3. 결과는 회의록 목록과 상세 화면에 `고객 승인 대기 / 고객 승인 / 고객 반려 / 승인 링크 만료`로 표시되고 고객 의견도 함께 보입니다.

- 링크는 한 번만 사용할 수 있고 기본 7일 뒤 만료됩니다. 다시 보내면 이전 링크는 무효가 됩니다.
- 고객에게는 발송 시점의 본문을 보여줍니다. 이후 본문을 수정하면 상태 옆에 `이전 본문 기준`이 표시됩니다.
- 회의록이나 프로젝트가 휴지통에 있는 동안에는 링크가 열리지 않고, 복원하면 다시 열립니다. 영구 삭제하면 요청 기록도 삭제됩니다.
- 메일 발송에 실패하면 아무것도 저장하지 않으며 이전 링크는 그대로 유효합니다.
- 고객 승인은 표시용 상태이며 요구·변경 이력에는 영향을 주지 않습니다.
- 이 패키지는 자기 PC(또는 설정한 사내 LAN)의 접속만 허용하므로, 고객 링크도 그 범위에서만 열립니다.

설정은 `b2-service/.env.example`을 `b2-service/.env`로 복사해 채웁니다. `.env`는 Git에서 제외되며, 바꾼 뒤에는 서비스를 다시 실행합니다.

| 이름 | 기본값 | 설명 |
| --- | --- | --- |
| `MAIL_MODE` | `console` | `console`: 보내지 않고 실행 창에 메일 내용과 링크 출력. `smtp`: 실제 발송 |
| `SMTP_HOST` / `SMTP_PORT` | 없음 / `587` | 예: `smtp.naver.com`, `smtp.gmail.com`. 465이면 SSL 접속 |
| `SMTP_USER` / `SMTP_PASSWORD` | 없음 | 메일 계정과 앱 비밀번호 |
| `MAIL_FROM` / `MAIL_FROM_NAME` | `SMTP_USER` / `PNT 회의록 서비스` | 보내는 주소와 표시 이름 |
| `APP_BASE_URL` | 비움 | 메일 속 링크의 앞부분. 비우면 PM이 접속 중인 주소를 사용. 이 서버가 응답하는 주소(`http://127.0.0.1:8773` 등)가 아니면 무시 |
| `APPROVAL_EXPIRE_DAYS` | `7` | 링크 유효 기간(일) |

기본값(`console`)에서는 메일 계정 없이 전체 흐름을 확인할 수 있습니다. 보낸 뒤 화면에 표시되는 승인 링크를 열면 됩니다.
기능 테스트는 `work/v3/test_approval.py`이며 실제 메일은 보내지 않습니다.

## AI 사용 준비

**모델 파일과 가상환경은 Git에 포함하지 않습니다.** 새 회의록 AI 분석과 생성형 답변에는 아래 준비가 필요합니다.

1. NVIDIA CUDA GPU·호환 드라이버를 준비합니다. 현재 생성 모델은 BF16 지원 GPU를 사용합니다.
2. `03_선택_AI환경설치.cmd` 실행.
3. `04_선택_모델다운로드.cmd` 실행 — 수 GB 다운로드, 고정 리비전의 공개 모델 사용.
4. `05_환경점검.cmd` 실행 후 서비스를 시작합니다.

| 용도 | 모델 | 위치 |
| --- | --- | --- |
| 회의록 분석·답변 생성 | unsloth/Qwen3-4B-Instruct-2507-bnb-4bit | b2-model/models/base/ (`B2_MODEL`로 다른 모델 선택 가능, 아래 "주제 묶기와 모델 비교") |
| 근거 의미 검색 | intfloat/multilingual-e5-small | b2-model/models/multilingual-e5-small/ |

기존에 받은 두 모델 폴더를 위 위치로 복사해도 됩니다. `.venv`는 복사하지 말고 설치 스크립트로 만듭니다.
모델이 없는 PC에서도 화면·프로젝트·파일 등록 등을 확인할 수 있으나 AI 분석은 완료되지 않습니다.
환경 점검 통과는 실제 추론 속도·가용 GPU 메모리·정확도까지 보장하지 않습니다.

## 주제 묶기와 모델 비교 (RTX 5090 기준)

회의록 분석 마지막 단계에서 AI가 각 행을 **무엇에 대한 이야기인지(주제)** 로 묶습니다. 안건 번호나 `[1]` 같은 표시가 없어도 내용으로 판단하고, 같은 프로젝트의 이전 회의에서 나온 주제(예: 납기·출하일·장비 입고 날짜)는 같은 주제로 연결합니다.

- 모델은 행 ID와 짧은 주제명만 돌려주며, 묶음 안의 문장은 모두 원문 그대로입니다.
- 머리 정보 행(회의명·일시·참석자 등)은 묶지 않고, 모델이 빠뜨린 행은 `기타`로 모읍니다.
- 결과는 회의록에 `agendas`로 저장되며 `/api/meetings/{회의록ID}` 응답에서 확인할 수 있습니다.
- 회의록 상세 화면의 **주제별 안건** 탭에서 주제마다 원문 문장, 같은 주제가 나온 같은 프로젝트의 다른 회의(눌러서 이동), `원문에서 보기`를 보여 줍니다. 본문을 수정한 뒤 다시 분석하기 전이면 이전 본문 기준이라고 표시합니다.
- 이 단계가 실패해도 회의록 분석은 정상 완료되고 `agenda_error`에 이유가 남습니다. `.env`에 `B2_AGENDA_GROUPING=0`을 넣으면 끕니다.

모두 Apache-2.0 공개 모델이며 고정 리비전으로 받습니다. 지금 설치된 라이브러리(`requirements-ai.txt`) 그대로 실행됩니다.

### 실행 순서

1. `03`, `04`를 이미 실행해 기본 AI 환경을 준비합니다.
2. `06_선택_비교모델다운로드.cmd` — 지금은 기본 모델 `qwen3-4b`만 확인·다운로드합니다(이미 있으면 받지 않음). 다른 모델이 필요하면 직접:
   `..\b2-model\.venv\Scripts\python.exe ..\b2-model\download_models.py --model qwen3-14b,qwen3-32b` (`b2-service` 폴더에서)
3. `07_선택_주제묶기비교.cmd` — 기본 모델 `qwen3-4b`만 테스트 회의록으로 채점합니다. 여러 모델 비교는 아래 직접 실행 옵션을 씁니다.
4. 결과는 `b2-service/data/agenda-benchmark/<실행 시각>/report.md`에 저장됩니다. 모델별 점수표와 회의록마다 어떤 행을 어떻게 묶었는지(틀린 행은 `✗ 정답:` 표시)가 들어 있습니다.
5. 고른 모델을 앱에 쓰려면 `b2-service/.env`에 `B2_MODEL=qwen3-14b`처럼 넣고 서비스를 다시 실행합니다. 이 값은 주제 묶기뿐 아니라 AI 정리·변경이력 추출 등 모든 AI 분석에 적용됩니다.

`b2-service` 폴더에서 직접 실행하는 옵션:

```powershell
..\b2-model\.venv\Scripts\python.exe -m work.v3.benchmark_agenda --check                       # GPU 없이 테스트 회의록·채점 확인
..\b2-model\.venv\Scripts\python.exe -m work.v3.benchmark_agenda --models qwen3-4b,qwen3-14b    # 일부 모델만
..\b2-model\.venv\Scripts\python.exe -m work.v3.benchmark_agenda --models all --think           # 생각 모드도 비교(참고용)
```

### 점수 읽는 법

| 항목 | 뜻 |
| --- | --- |
| 회의 안 묶기 | 한 회의 안에서 같은 주제인 행끼리 같은 묶음에 들어갔는지(행 쌍 기준 F1) |
| 회의 간 연결 | 다른 회의의 같은 주제가 같은 주제 ID로 연결됐는지(행 쌍 기준 F1) |
| 종합 | 두 점수의 평균. 1.0이면 정답과 같습니다 |
| 주제 수 오차 | 회의당 주제 개수가 정답과 평균 몇 개 다른지 |

표 위쪽의 `(참고) 정답 그대로`(1.0)와 `(참고) 회의마다 한 묶음`(약 0.1)은 점수의 상한과 바닥을 보여 주는 기준선입니다. 생각 모드 결과는 참고용이며 앱은 생각 모드를 쓰지 않습니다.

### 테스트 회의록

`b2-service/work/v3/agenda_samples/`에 가상 프로젝트 3개, 회의 10건이 있습니다. 번호 없는 서술형, 발언자 표기, 짧은 메모, Word 표(`구분 | 내용`) 형식을 섞었고, 같은 대상을 다른 말로 부르거나(납기·납품일·출하·입고) 비슷한 말이 다른 대상을 가리키는 경우(안전 커버·커버 도장)를 넣었습니다.

두 번째 세트 `b2-service/work/v3/agenda_samples_2/`에도 가상 프로젝트 3개, 회의 10건이 있습니다(노칭·스태킹기 4건, 전해동박 제박기 3건, 진공건조·AGV 반송 3건). 번호 안건이 주제와 맞지 않는 경우(`3. 기타` 아래 여러 주제), `[결정 사항]`/`[미결 사항]`처럼 문장 종류로 나눈 섹션, 3열 Word 표, 비슷한 말이 다른 주제인 경우(정렬용 CCD·외관 AOI 카메라, 진공도·진공 펌프, 드라이룸·퍼지 가스 이슬점)를 넣었고, 값 변경·보류·철회·원복(처리량 24→30→24롤) 같은 변경이력이 회의마다 이어집니다. 기본 비교는 첫 세트만 쓰므로 이 세트는 `--samples work/v3/agenda_samples_2`로 실행합니다. `회의록/` 폴더의 `.txt`는 같은 회의를 앱에 바로 등록할 수 있게 옮긴 것이며 파일명 앞 번호가 프로젝트(`01`~`03`)와 회의 순서입니다.

실제 회의록을 추가하려면 같은 형식의 `.json` 파일을 만들어 이 폴더나 별도 폴더(`--samples 폴더`)에 둡니다. 각 행 앞에 정답 주제 키를 붙이고, 머리 정보 행은 `meta`, 주제가 없는 행(인사·다음 회의 안내)은 `etc`로 표시합니다. `meta` 표시와 머리 정보 행 판단이 다르면 실행 전에 알려 줍니다. 실제 회의록은 Git에 올리지 않도록 별도 폴더 사용을 권합니다.

## 입력 자료와 원본 미리보기

- Word `.docx`, 글자가 포함된 PDF, Excel `.xlsx`, 텍스트 `.txt`·`.md` 지원.
- Excel은 셀 텍스트를 읽습니다. 색상 막대·도형만으로 표현한 간트 기간은 해석하지 않습니다.
- 스캔 PDF·이미지 OCR은 지원하지 않습니다. 파일당 최대 8MB이며 긴 문서는 나누어 등록합니다.
- Word 원본 페이지 미리보기에는 Microsoft Word 데스크톱 프로그램이 필요합니다.
  Word가 없으면 추출한 텍스트로 확인합니다.

## 저장·Git 업로드

- 소스 업로드 대상은 **이 v4 폴더 전체**입니다. `.gitignore`, `.gitattributes`도 함께 올립니다.
- 로컬 데이터는 `b2-service/data/v4/`에 생성되며 Git에서 제외됩니다.
- `.venv`, `models`, `node_modules`, 업로드·SQLite DB·로그·비밀 설정도 제외됩니다.
- 서버 실행 중 데이터를 덮어쓰지 않습니다. 업데이트 전 필요 데이터는 별도로 백업합니다.
- 기본 실행은 자기 PC의 `127.0.0.1`에만 연결합니다. 비밀번호 없는 테스트 로그인을 인터넷 공개 배포에 그대로 사용하면 안 됩니다.
- AWS·Supabase 공유 데이터베이스 연결은 이 패키지에 포함되지 않습니다.

## 개발

실행 진입점은 **`work.v3.server:app`**입니다. 루트 `server.py`를 직접 실행하지 않습니다.
프런트엔드를 수정할 때만 Node.js/npm이 필요합니다. `b2-service`에서 실행합니다.

```powershell
npm ci
npm run build
npm test
..\b2-model\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
..\b2-model\.venv\Scripts\python.exe -m pytest work/v3 -q
```

기능 테스트는 임시 데이터와 통제된 AI 응답을 사용합니다. 실제 모델의 정확도·속도 검증과는 별개입니다.
